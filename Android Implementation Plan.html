Android Implementation Plan

Porting the AcademyTest app from SwiftUI to Jetpack Compose

🗂 App Overview

A simple item management app. Displays a sorted list of items (animals with emojis), each with a name and a favorite flag. Users can add, delete, and toggle favorites. Selecting an item opens a detail view. The UI is in Italian.

  • No persistence — state is in-memory only
  • Sorted alphabetically (case-insensitive), tiebroken by insertion order
  • Architecture: MVVM

📦 Data Model

Swift — ItemViewModel.swift

A mutable reference type (@Observable class). Views observe it directly and react when name or isFavorite changes.

@Observable final class ItemViewModel: Identifiable, Hashable {
    let id: UUID
    let creationIndex: Int   // insertion-order tiebreaker
    var name: String
    var isFavorite: Bool
}

Kotlin — Item.kt

An immutable data class. Never mutate it directly — replace it in the list with item.copy(...).

data class Item(
    val id: UUID = UUID.randomUUID(),
    val creationIndex: Int,
    val name: String,
    val isFavorite: Boolean
)

Kotlin — ItemsListViewModel.kt

Extends ViewModel(). Uses mutableStateListOf<Item>() so Compose recomposes automatically on list changes. Toggle favorite is an explicit method (since data classes are immutable).

class ItemsListViewModel : ViewModel() {
    val items = mutableStateListOf<Item>()
    var selectedItemId: UUID? by mutableStateOf(null)

    val sortedItems get() = items.sortedWith(
        compareBy(String.CASE_INSENSITIVE_ORDER) { it.name }
            .thenBy { it.creationIndex }
    )

    fun addItem(name: String) { ... }
    fun toggleFavorite(item: Item) { items[indexOf(item)] = item.copy(isFavorite = !item.isFavorite) }
    fun deleteItems(ids: Set<UUID>) { ... }
    fun deleteFromDetail(item: Item) { items.remove(item); selectedItemId = null }
}

Swift — AddItemViewModel.swift → Kotlin local state

Ephemeral — lives only while the add sheet is open. In Kotlin, use remember { mutableStateOf("") } inside the sheet composable instead of a separate ViewModel class.

  • name — the text field value
  • trimmedName — whitespace stripped
  • canSave — true when trimmedName is not empty

🔄 Key Concept Translations

Swift

@Observable class — mutable reference type, views observe changes automatically

Kotlin

data class + mutableStateListOf — immutable value, replace in list to trigger recompose

Swift

@Binding var isFavorite: Bool — two-way binding, child can write back to parent

Kotlin

isFavorite: Boolean, onToggle: () -> Unit — state hoisting: value flows down, events flow up

Swift

@Environment(\.dismiss) — auto-injected dismiss action

Kotlin

onDismiss: () -> Unit lambda — passed explicitly from the parent

Swift

Kotlin

NavigationSuiteScaffold — same adaptive behavior on tablet vs phone

Swift

.sheet(item:) — shows a sheet when a value is non-nil

Kotlin

if (showSheet) { ModalBottomSheet(...) } — gated by a Boolean state

Swift

#Preview — live preview in Xcode canvas

Kotlin

@Preview(showBackground = true) — live preview in Android Studio

🔁 Data Flow

ItemsListViewModel (single source of truth) │ ├── ContentScreen │ ├── ItemsListScreen │ │ ├── ItemRow ──▶ FavoriteButton │ │ │ (calls toggleFavorite up to ViewModel) │ │ └── AddItemSheet │ │ (calls addItem up to ViewModel on save) │ └── ItemDetailScreen │ ├── FavoriteButton (calls toggleFavorite up) │ └── Delete button (calls deleteFromDetail up)

Every mutation flows upward to the ViewModel via a lambda callback. This is identical in spirit to SwiftUI's @Bindable, just made explicit. No child composable writes state directly.

🛠 Phase 1 — Project Setup (before writing any code)

  1. Add the Kotlin plugin The generated project is missing it. Add alias(libs.plugins.kotlin.android) to both build.gradle.kts files and declare it in libs.versions.toml. Without this, Kotlin won't compile at all.
  2. Enable Compose in app/build.gradle.kts Add buildFeatures { compose = true } inside the android { } block. This activates the Compose compiler.
  3. Add all Compose dependencies to libs.versions.toml Declare versions and library entries for: Compose BOM, compose-ui, material3, material3-adaptive, lifecycle-viewmodel-compose, navigation-compose, and activity-compose. 
    [versions]
composeBom         = "2024.09.00"
lifecycleViewModel = "2.8.7"
navigationCompose  = "2.8.5"
activityCompose    = "1.9.3"

[libraries]
compose-bom                 = { group = "androidx.compose", name = "compose-bom", version.ref = "composeBom" }
compose-ui                  = { group = "androidx.compose.ui", name = "ui" }
compose-material3           = { group = "androidx.compose.material3", name = "material3" }
compose-material3-adaptive  = { group = "androidx.compose.material3.adaptive", name = "adaptive" }
compose-ui-tooling-preview  = { group = "androidx.compose.ui", name = "ui-tooling-preview" }
compose-ui-tooling          = { group = "androidx.compose.ui", name = "ui-tooling" }
lifecycle-viewmodel-compose = { group = "androidx.lifecycle", name = "lifecycle-viewmodel-compose", version.ref = "lifecycleViewModel" }
navigation-compose          = { group = "androidx.navigation", name = "navigation-compose", version.ref = "navigationCompose" }
activity-compose            = { group = "androidx.activity", name = "activity-compose", version.ref = "activityCompose" }
  4. Reference the dependencies in app/build.gradle.kts Add them to the dependencies { } block, using the BOM to manage Compose versions automatically. 
    implementation(platform(libs.compose.bom))
implementation(libs.compose.ui)
implementation(libs.compose.material3)
implementation(libs.compose.material3.adaptive)
implementation(libs.compose.ui.tooling.preview)
debugImplementation(libs.compose.ui.tooling)
implementation(libs.lifecycle.viewmodel.compose)
implementation(libs.navigation.compose)
implementation(libs.activity.compose)
  5. Sync Gradle and verify the project builds clean In Android Studio: File → Sync Project with Gradle Files. Fix any version conflicts before writing any code. A clean build here saves hours of debugging later.
  6. Update MainActivity to use Compose The generated MainActivity uses the old XML/View system. Replace its body with setContent { } — the Compose entry point. This is where ContentScreen will eventually be called. 
    class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            AcademyTest2026Theme {
                // ContentScreen() will go here
            }
        }
    }
}
  7. Create the package folder structure Inside app/src/main/java/com/example/academytest2026/, create two sub-packages: model/ for data classes and ui/ for all composables and ViewModels.

🏗 Phase 2 — Build Order (file by file)

  1. Item.kt The data class. No UI — just pure Kotlin. Verify it compiles.
  2. ItemsListViewModel.kt All business logic: add, delete, toggle, sort. Still no UI.
  3. FavoriteButton.kt Smallest composable. Good first test of Compose + @Preview.
  4. ItemRow.kt Row layout with name, subtitle, and FavoriteButton. Add a @Preview with sample data.
  5. AddItemSheet.kt ModalBottomSheet with TextField, Annulla and Salva buttons. Auto-focus the text field on appear.
  6. ItemsListScreen.kt LazyColumn + SwipeToDismissBox + TopAppBar with + button + empty state composable.
  7. ItemDetailScreen.kt Detail layout with TopAppBar delete action and FavoriteButton.
  8. ContentScreen.kt Wire everything together with NavigationSuiteScaffold. Plug in ItemsListViewModel here as the single source of truth.
  9. Wire ContentScreen into MainActivity + run the app Replace the placeholder in setContent { } with ContentScreen(). Launch on emulator or device and verify all features work end-to-end.
